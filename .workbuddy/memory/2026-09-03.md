## 🔴 修复文本解析器致命死循环（坐标列非有限时卡死浏览器）

为给对话框加解析失败的具体提示，在 `parseTextPoints` 主循环里加了「坐标非有限 → coordBad++ 并 continue」分支——结果暴露一个**原本就存在的致命 bug**：该 `continue` 跳过了循环底部的 `i = next`，导致当某行 `res.count>=3` 但坐标列非有限时，`i` 永远不前进，**同一行无限重读 → 死循环**。只要所选坐标列整列非数值（或分隔符识别错位使坐标列错位），就会**卡死浏览器标签页**而非报错。

### 修复
- `src/io/text.ts` 主解析循环：去掉 `continue`，改为 `if (坐标均有限) { 填充+rows++ } else { coordBad++ }`，保证 `i = next` 始终执行。
- 顺带把原有的「未解析到任何有效数据行」泛化错误，改为按 `coordBad`/`dataRows` 给出具体提示（坐标列全非有限 / 部分缺失 / 分隔符表头识别有误），并复用已上移的 `delimLabel`。
- `scripts/smoke.ts` 第 8 段新增「错误坐标列选择给出具体提示」用例（CSV `name,x,y,z` 强制选 name 为 X）。
- 临时 `scripts/textcheck.ts` 定位死循环后已删除。

### 验证
- 定向复现：选 name 列为 X → 修复前 `node` 进程被 `timeout 30` 杀掉（事件循环被同步死循环阻塞，连 8s 超时回调都无法触发）；修复后正确抛出「已读取 2 行数据，但所选 X/Y/Z 坐标列全部为非有限数值…」并退出。
- `tsc --noEmit` 通过；`npm run smoke` 全量后台复跑中（该套件在本沙箱对 180k/900k 点云做端到端剖分较慢，约 10 分钟；文本解析段已通过定向验证）。

### 教训
- `while` 循环体内用 `continue` 时，凡在 `continue` 之后才有「推进游标」语句的，必死循环。给解析器加错误分支时务必保证游标推进不被跳过。
- 对话框层的「非数值列拦截」只能挡住 UI 路径；**解析层必须自己兜住**，否则分隔符错位等自动识别场景仍会触发底层死循环。

## 视角面板：平面旋转按钮 + 面板展开按钮（第二版修正）

### 坐标系约定（重要）
本项目为 **Y-up**：GridHelper 默认铺在 XZ 平面（法线 Y），UI 中「XZ 平面（水平）」即水平面，`camera.up` 默认 `(0,1,0)` 是正确的。
因此 **XY 平面旋转 = 绕 Z 轴**、**YZ 平面 = 绕 X 轴**、**XZ 平面 = 绕 Y 轴**。

### 1. 旋转功能（首版有误，已重写）

- **首版问题**：`rotateAroundAxis` 只转 `camera.position` 并把 up 强行设为 `(0,1,0)`。绕 X/Z 轴旋转会改变 OrbitControls 的极角 phi，经过极点时其 `spherical.makeSafe()` 会 clamp → 旋转卡死/跳变，用户体验为「不对」。
- **修正**：改为 `rotateInPlane(plane: 'xy'|'yz'|'xz', deg)`，**`camera.up` 跟随旋转一起转**（`up.applyAxisAngle(axis, rad)`），保持相机姿态连续，彻底绕开极点 gimbal lock。
- UI 按「平面」而非「轴」命名，符合用户心智：每个平面一行 `[XY 平面] [↺][↻]`，每步 15°。
- 附带 `resetUp()` 按钮；`setViewAxis()` 与 `frameBounds()` 均重置 up 为 `(0,1,0)`（预设视角/按 F  framing 方向是固定 iso 向量，必须配世界 Y-up 才正确）。
- `base.css` 新增 `.rot-row` / `.rot-plane` 样式。

### 2. 面板展开按钮（首版不可见，已修复）

- **问题**：折叠后面板完全隐藏，无 UI 可重新展开。
- **首版不可见的根因**：`.workspace` **没有 `position: relative`**（只有 `.viewport` 有），导致 `.expand-tab` 的 `position:absolute` 定位基准跑到页面根而非 workspace；同时 HTML 的 `hidden` 属性与 CSS `display` 双重控制打架；CSS 里还有一处多余的 `scaleX(-1)` 会把右侧箭头翻错方向。
- **修正**：`.workspace` 加 `position: relative`；移除 `hidden` 属性（纯 CSS 控制显隐）；删掉 `scaleX(-1)`（SVG 路径本身已是正确的左箭头）。
- `app.ts` 绑定 `#leftExpand` / `#rightExpand` → `togglePanel()`。

### 验证
`scripts/rotate-expand-probe.mjs` **23/23**。判据：绕某平面旋转时该平面**法线轴坐标必须不变**（Δ=0.0000）、轨道半径保持不变、相机确实在平面内移动；展开标签折叠后可见/有尺寸/在视口内/点击可复原。

**探针编写注意**：载入点云会触发 `frameAll` 缓动动画，且 OrbitControls 开了 damping，测量相机位置前必须轮询等待位置稳定，否则首项测量会取到动画中间值而误报。

## 鼠标旋转"奇怪" bug 修复（OrbitControls up 四元数陷阱）

**现象**：用户反馈三维点云区域鼠标移动旋转有点奇怪。

**根因**：上一版 `rotateInPlane` 把 `camera.up` 跟随旋转一起转（绕 X/Z 轴时 up 倾斜），而我没意识到 **OrbitControls 在构造函数里就把 `_quat = setFromUnitVectors(up, +Y)` 缓存、之后永不刷新**（three 0.169 `OrbitControls.js:132`）。于是：
- `controls.update()` 用**旧** `_quat` 算球面旋转 → 相机位置绕世界 Y 公转
- `lookAt()` 用**新**的倾斜 up → 画面被拧了 N°

位置旋转轴和滚转脱节 → 画面歪斜、拖拽手感错乱。这是用户说的"奇怪"。

**我第一版尝试的修复是错的**：加 `syncControlsUp()` 强制把 `_quat` 同步到新 up。验证发现四元数同步了，但**拖拽时画面 roll 跳变 41°**（绕倾斜轴公转必然持续翻滚）——反而更糟。

**正确修复**：**不碰 `camera.up`**，只旋转相机位置，`up` 恒为世界 Y。`controls.update()` 重算球面并 lookAt，OrbitControls 模型始终一致。移除了 `syncControlsUp()`、`resetUp()` 及 UI 的"重置上方向"按钮（up 不再会变）。

**关键实证**：`scripts/orbit-drag-probe.mjs` 测了"绕 Z 轴转 24×15°=360°"，完整跑完 24/24、回误差 0% —— 证明当初我担心的 gimbal lock **从未真实存在**，加 up 跟随纯属过度设计。以后做相机旋转，**除非真要改 up 语义，否则只转 position + 保持世界 Y up**。

**教训**：改 `camera.up` 前先查 OrbitControls 是否缓存了基于 up 的四元数；不要凭理论推测加"防 gimbal lock"逻辑，要用探针实测（整圈旋转）验证是否真有问题。

### 验证

- `scripts/rotate-expand-probe.mjs` 23/23 无回归。
